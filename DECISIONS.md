# Decisions

## llms-full.txt is built in Ruby from the rendered markdown twins

`llms.txt` is a Liquid template, but `llms-full.txt` is generated by `_plugins/markdown_page_generator.rb` in a `:site, :post_render` hook that concatenates each twin's rendered `output`.

As a template, `llms-full.txt` depended on render order: posts render before pages, so `post.content` was already HTML, while `page.content` on the twins was still unrendered Liquid (`{% include_relative %}`, `{{ site.author... }}`). Building from the twins after everything has rendered means each section is identical to its `.md` file, whatever the render order.

Using pre-render post markdown instead was rejected because it would put raw `{% include youtube_player.html %}` tags in `llms-full.txt` while the `.md` twins have them expanded.

## Site search ranks titles, descriptions, tags and search terms with MiniSearch

`/search/` and `/posts/` load `search.json` (every post, every titled page, and the external links in `_data/search_links.yml`) into MiniSearch in the browser. Title matches count most, then tags and `search_terms`, then descriptions. Prefix matching is always on; typos are allowed only in words of 5+ letters, because allowing them in shorter words made "llm" match "Lam". Stop words such as "of" and "the" are left out of the index, and out of a query once the visitor types past them, so "south of france" searches "south france" (50 hits instead of 179, mostly prefix matches on "of"). A stop word still being typed is kept, because "the" may become "theatre". The cost is that a query that depends on one, like "it crowd", searches only "crowd".

On 30 test queries (titles, typos, accents, plurals and words only in a page's body), MiniSearch put the right page in the top 3 for 29. SimpleJekyllSearch, which this replaced, managed 8: it only indexed posts and returned the first 10 records whose fields contained the query's letters in order, unranked. Fuse.js also scored 29 but each query took about 21 times as long. Pagefind scored 25 and found 2 of 7 typos.

The index leaves out body text. It is 17 KB gzipped against 407 KB with full text, and only 1 of the 30 queries needed the body. Body text would also need a `:post_render` hook, for the same render-order reason as `llms-full.txt` above. Words a visitor might search for that aren't in the title, description or tags go in `search_terms` in front matter instead; for a signed file, that means re-signing it. With about 34 terms on every post, the index is 69 KB gzipped, still a sixth of the full-text size.

## Signatures are published beside each page's .md version

`_plugins/signature_files.rb` copies each post's and each `signed: true` page's `.asc` into the site unchanged, at the page's URL with `.md.asc` in place of the trailing slash: `/2026/11/dashcam-footage-to-3d-driving-game.md.asc`. `_includes/signature.html` links to it and uses it in the `gpg --verify` example.

They used to be served from `raw.gregology.net`, a proxy of the GitHub repo's raw files. Publishing them with the site removes that dependency, and makes the link's `download` attribute work, because browsers ignore it on links to another domain.

The signature covers the source file in `_posts/` (or the page's `.md`), front matter included, not the generated `.md` beside it, which has its front matter replaced by a heading and its Liquid rendered. A clear-signed file carries its own copy of the text, so `gpg --verify` needs only the `.asc`. Serving it at the source path (`/_posts/2026-11-04-...md.asc`) was rejected as less tidy.

## The timeline stays markdown and is laid out in the browser

`timeline.md` is year headings, month headings and one emoji-led line per milestone. `js/timeline.js` rebuilds those as a line down the page, coloured by where Greg was living, and draws Greg's Clock (every week of an 86-year life as a square) into an empty `<div>`.

Moving the milestones into a `_data` file rendered with Liquid was rejected. A page's `.md` twin, and so `llms-full.txt`, is its source with the Liquid rendered, so both would carry generated HTML instead of readable markdown. The clock's script moved out of the page for the same reason: the twin used to include it.

The costs: without JavaScript the page is plain headings with no clock, and the places lived are repeated in `PLACES` in `js/timeline.js`, because they colour whole years and the markdown has nowhere to hold that.

## Comments, videos and icons load only what a reader uses

A post with a video loaded about 2 MB of third-party script before the reader scrolled or clicked anything: Disqus and the trackers it brings, YouTube's player, and Font Awesome's 1.5 MB script, which drew 17 icons.

- Disqus loads once the page has finished loading and the reader is within 400px of the comments, or straight away for a link to a comment (`_includes/disqus.html`). A "Show comments" button was rejected so comments still appear without a click. A short post still loads Disqus, but only after the page has loaded.
- A YouTube video is its thumbnail with a play button until it's clicked (`_includes/youtube_player.html`, `js/youtube-player.js`). Without JavaScript the thumbnail links to the video on YouTube.
- Icons are inline SVGs from `_data/icons.yml`, copied from Font Awesome Free. The footer's icons draw the same shapes Font Awesome layered, and render pixel-identical. A new icon needs its width and path copied from Font Awesome into that file.
- Google Fonts load with `display=swap`, so text shows in a fallback font until the web font arrives instead of being hidden for up to 3 seconds. Self-hosting the fonts would avoid the swap but was rejected: GitHub Pages caches every file for 10 minutes, while Google caches font files for a year.
- The fallback fonts are Times New Roman and Arial, stretched to the width and line height of Lora and Open Sans (the "fallback" faces at the top of `css/main.css`). Unstretched, Lora is 14% wider than Times New Roman, so paragraphs rewrapped when it arrived and the page jumped. A new weight of either font needs its own fallback face, measured the same way.
